Comandos auxiliares · disponibles en todo momento

onix use

$ onix use /path/to/vault
Persiste un default global del vault en ~/.config/onix/config.json. Evita repetir --vault. onix use --clear lo elimina.

onix status

$ onix status
Inspecciona en cualquier estado: vault resuelto, Active Session, Patch Plans con progreso (X de Y decididos), Rule Candidates pendientes y Classification Rules aprobadas.

onix review --approve-rule

$ onix review <plan> --approve-rule rule-candidate-1
Convierte un Rule Candidate (creado por cada move) en una Classification Rule versionada. Sin esta aprobación, las correcciones nunca se vuelven reglas implícitas.

Comandos del flujo principal

02 Capturar

Una Ephemeral Session a la vez. El Session Inbox es un .md visible en Obsidian; el Active Session vive en .onix/state/ y es lo que permite encontrar el inbox aun si lo renombrás.

  • $ pnpm onix --vault /path/to/vault start
    Crea Onix/Sessions/session-inbox-YYYYMMDD-HHMMSS.md y .onix/state/active-session.json. Falla si ya hay un Active Session.
  • $ pnpm onix close --no-review
    Genera el Patch Plan sin abrir la Integrated Review. Útil para automatización o tests; quedan los archivos para onix review después.

03 Proponer y revisar

La Proposal Engine consulta el Vault Index y las Classification Rules para clasificar Learning Captures en seis categorías: Consolidated Knowledge, Knowledge Refinement, Research Candidate, Reference Item, Sensitive Candidate y No Consolidation Candidate.

  • $ pnpm onix close
    Indexa el vault, selecciona Candidate Notes, genera Patch Plan y lanza la Integrated Review interactiva por defecto.
  • $ pnpm onix review stubbed-plan
    Reanuda la Integrated Review. Usa $VISUAL / $EDITOR para edit y split.
  • $ pnpm onix review stubbed-plan --render
    Imprime el Review Rendering en Markdown sin grabar Approval State.
  • $ pnpm onix review stubbed-plan --approve item-1
    Flags low-level disponibles para automatización: --edit, --move, --split, --discard.

04 Aprobar reglas

Cada move en la review crea un Rule Candidate en el Approval State. Sólo cuando lo aprobás explícitamente se persiste en el Classification Rules Store; en la próxima sesión, esa regla guía la propuesta para captures con el mismo patrón.

  • $ pnpm onix review stubbed-plan --approve-rule rule-candidate-1
    Escribe la regla en vault/.onix/classification-rules.json, el único archivo bajo .onix/ considerado Versioned Tool State (apto para Git).

05 Aplicar y versionar

El Local Validator chequea el Write Boundary y la Commit Validation antes de escribir nada. Si una nota destino cambió desde la propuesta, apply aborta y deja el Session Inbox intacto.

  • $ pnpm onix apply stubbed-plan
    Escribe sólo ítems con Review Action de approve, edit, move o split. Discarded y pending se ignoran. Las Knowledge Refinements reemplazan in-place el párrafo coincidente.
  • $ pnpm onix apply
    Si existe un único Patch Plan, apply infiere el identificador. Tras escribir verifica, borra el Session Inbox y termina con Versioning Review (lista archivos cambiados, no hace commits).

Review Actions disponibles

a
Approve

Acepta el ítem tal cual fue propuesto.

e
Edit

Abre $VISUAL/$EDITOR con el contenido propuesto.

m
Move

Cambia el destino; genera un Rule Candidate.

s
Split

Divide en dos o más Learning Captures usando --- part ---.

d
Discard

Marca el ítem para no escribirlo en el vault.
